# Сравнение алгоритмов кластеризации в DCM и AAMCC

## 1. Введение

В DCM (Dubna Cascade Model) объединение нуклонов в префрагменты (коалесценция) реализовано в подпрограммах `BCOAV1` / `BCOAV2`.
В AAMCC (Abrasion-Ablation Monte Carlo for Colliders) для той же цели используется алгоритм MST (Minimum Spanning Tree) с возможностью учёта импульсов (фазовая метрика).

Ниже приведено детальное сопоставление этих двух подходов.

---

## 2. Алгоритм DCM: `BCOAV1` / `BCOAV2`

### 2.1. Критерии объединения

Нуклоны объединяются в один фрагмент, если **одновременно** выполнены два условия:

1. **Критерий относительной скорости**
   Нуклон присоединяется к фрагменту, если его скорость в системе покоя фрагмента меньше порога:

   |v_rel| < sqrt(VV0MAX) · c

   В коде:

   ```fortran
   VV = VSNX**2 + VSNY**2 + VSNZ**2
   IF (VV .GT. VV0) IRE = 1   ! не присоединять
   ```

   Параметр `VV0MAX = 0.045` соответствует |v_rel| < 0.212·c.

2. **Критерий пространственного расстояния**
   Расстояние между нуклоном и центром фрагмента (с учётом лоренцева сжатия по Z) должно быть меньше:

   Δr < RR0MAX · A_frag^(1/3)

   В коде:

   ```fortran
   RPPMAX = RR0MAX * (APP**0.33333)
   RR = SQRT( (X1F-XKSS)**2 + (Y1F-YKSS)**2 + GAMR*(Z1F-ZKSS)**2 )
   IF (IR0MAX .EQ. 1 .AND. RR .GT. RPPMAX) IRE = 1
   ```

   Параметры: `IR0MAX = 1` (включить координатную кластеризацию), `RR0MAX = 2.0` фм.

### 2.2. Алгоритм объединения

Используется жадная итеративная процедура с постепенным увеличением порога по скорости:

```fortran
NMAX = 3
DO IT = 1, NMAX
   VV0 = VV0MAX * IT / NMAX
   CALL BCOAV2(VV0)   ! объединяем только самые близкие пары
END DO
```

На каждом шаге перебираются все пары частиц, и если оба критерия выполнены, они сливаются в один фрагмент.
Такой подход гарантирует, что сначала объединяются самые «тесные» пары.

### 2.3. Особенности

- Лоренцево сжатие продольной координаты: `GAMR = 1/(1 - VZ²)`.
- Радиус захвата растёт с массой фрагмента как A^(1/3).
- Учёт античастиц и гиперонов (в других частях кода).
- Порог по скорости фиксирован: v_rel < 0.212·c.

## 3. Алгоритм AAMCC: MST с фазовой метрикой

### 3.1. Критерий объединения

Строится полный граф, в котором вес ребра между двумя нуклонами вычисляется как:

    w = sqrt( Δr² / r0² + Δp² / p0² )

где:

- Δr² = Δx² + Δy² + Δz² — пространственное расстояние (фм),
- Δp² = Δp_x² + Δp_y² + Δp_z² — разность импульсов (МэВ/c),
- r0 = 1.0 фм — масштаб длины,
- p0 = 300 МэВ/c (по умолчанию) — масштаб импульса.

Затем строится минимальное остовное дерево (MST). Рёбра с весом w > d_min разрываются.
Оставшиеся связные компоненты считаются фрагментами.

### 3.2. Параметры

- `dmin` — критическое расстояние (аналог порога).
- `p0` — масштаб импульса; если `p0 ≤ 0`, импульсная часть отключается (чисто пространственный MST).
- `r0` — масштаб длины (обычно 1 фм).

### 3.3. Особенности

- Единая метрика: пространственная и импульсная части **складываются** в квадратах.
- MST даёт глобально оптимальную структуру связей.
- Нет явного учёта A^(1/3) для радиуса захвата.
- Нет лоренцева сжатия по Z.
- Порог `dmin` может быть фиксированным или зависеть от энергии возбуждения (в оригинальном AAMCC).

---

## 4. Прямое сопоставление

| Аспект | DCM (`BCOAV`) | AAMCC (MST + фазовая метрика) |
|--------|---------------|-------------------------------|
| **Логика** | **И** (оба критерия обязательны) | **Взвешенная сумма** (квадратичное сложение) |
| **Критерий по скорости** | v_rel < 0.212·c (фиксирован) | Δp / p0 с настраиваемым p0 |
| **Эквивалентный масштаб импульса** | p ≈ 200 МэВ/c | p0 = 300 МэВ/c (по умолчанию) |
| **Критерий по координатам** | Δr < 2 · A_frag^(1/3) фм | Δr / r0 < d_min (без масштаба с A) |
| **Порог** | VV0MAX = 0.045 (скорость) + RR0MAX = 2.0 фм | dmin (обычно 1.8–2.7 фм) |
| **Алгоритм** | Жадный, 3 итерации с ростом порога | MST — оптимальная глобальная структура |
| **Анизотропия** | Лоренцево сжатие по Z (GAMR) | Отсутствует |
| **Масштаб с A** | Радиус захвата ∝ A^(1/3) | Отсутствует |

### 4.1. Ключевые различия

1. **Логика объединения**
   - DCM: «нуклоны объединяются, только если **одновременно** близки по скорости и по координате».
   - AAMCC: «нуклоны объединяются, если **сумма** нормированных квадратов меньше порога».
   Это приводит к разному поведению в крайних случаях:
   - Далеко (Δr = 3 фм), но одинаковые импульсы: DCM не объединит, AAMCC может объединить (если dmin > 3).
   - Рядом (Δr = 0.5 фм), но Δp = 500 МэВ/c: DCM не объединит, AAMCC тоже не объединит (импульсная часть >> dmin).

2. **Эквивалентный масштаб импульса**
   DCM: v_rel < 0.212·c эквивалентно p ≈ 200 МэВ/c.
   AAMCC по умолчанию: p0 = 300 МэВ/c, что в 1.5 раза мягче.

3. **Масштабирование с A**
   DCM: RPPMAX = 2 · A_frag^(1/3) — чем крупнее фрагмент, тем больше его радиус захвата.
   AAMCC: MST работает с постоянным dmin для всех пар.

4. **Итеративность**
   DCM: жадный алгоритм с 3 шагами, сначала сливаются самые близкие пары.
   AAMCC: MST строит сразу глобальную структуру.

5. **Лоренцево сжатие**
   DCM: учитывает сжатие продольной координаты в системе покоя фрагмента.
   AAMCC: все три координаты равноправны.

---

## 5. Рекомендации по сближению подходов

Если требуется, чтобы AAMCC давал результаты, близкие к DCM, можно предпринять следующие шаги:

1. **Уменьшить `p0` до 200 МэВ/c** — это эквивалент v_rel = 0.212·c.

2. **Перейти от аддитивной метрики к логике «И»**
   Вместо `sqrt(Δr²/r0² + Δp²/p0²) < dmin` использовать два раздельных критерия:

   ```
   (Δr < dmin_r) И (Δp < dmin_p)
   ```

3. **Ввести масштаб `dmin_r ∝ A_cluster^(1/3)`**
   Аналогично RPPMAX в DCM. Это потребует пересчёта рёбер при росте кластера.

4. **Учесть лоренцево сжатие**
   Умножать продольную разность координат на GAMR = 1/(1 - VZ²) в системе покоя фрагмента.

---

## 6. Заключение

DCM использует **коалесценцию с двумя независимыми порогами**:
`v_rel < 0.212c` **И** `Δr < 2·A^(1/3) фм`.

AAMCC применяет **единую фазовую метрику**:
`sqrt(Δr² + (Δp/p0)²) < dmin`, где пространственная и импульсная части складываются.

Это принципиально разные подходы. DCM жёстче отсекает пары, у которых хотя бы один параметр превышает порог.
AAMCC более «терпим»: большая компонента может компенсироваться малой другой.

Для достижения согласия между моделями требуется настройка `p0` и переход к раздельным критериям.
